## Code changes

### 1. Planner rewritten (`agent/planner.py`)
- The regex rules are gone. **One LLM call** now returns `{"intent": ..., "questions": [...]}`, merging classification and question splitting (it replaces the old second `split` call).
- Intents are now `lookup`, `market` (renamed from `context`), `decision` and `out_of_scope`.
- Invalid or unparseable output defaults to `lookup`, never to `out_of_scope`.
- Sub-questions are used only for lookup and market, only when there are at least 2, deduplicated and capped at 3.
- `find_companies` is unchanged. The `source` field (rules or llm) was removed from the planner result and the trace.

### 2. Early exit for out-of-scope questions
- `agent/nodes.py`: `planner_node` writes a fixed message as `answer` for `out_of_scope`, and `route_after_plan` returns `END`.
- `agent/graph.py`: `END` added to the planner's conditional edge targets.
- No RAG, news, synthesizer or critic runs for these questions.

### 3. Other files touched for the above
- `rag/llm.py`: the dummy backend's `split` entry was removed. The dummy `plan` reply is now `{"intent": "lookup", "questions": []}`.
- `app.py`: the example button "Context" became "Market". The "RAG output" tab only appears when RAG ran, so out-of-scope answers don't crash the UI.
- `tests/test_planner.py`: rewritten to stub the LLM and test the plumbing (valid labels, invalid-output fallback, split rules, cap, deduplication, no split for decision and out_of_scope). It does not test classification quality.
- `eval/agent_cases.csv`: `context` renamed to `market`, and 8 cases added (28 total). Added cases:
  - 3 paraphrased decisions with no trigger words;
  - 2 market questions phrased differently;
  - 3 clearly unrelated questions, expected to return the out-of-scope message.

### 4. `doc_type` removed from the production rewrite (`rag/graph.py`)
- The rewrite prompt no longer asks for `doc_type`, and `analyze(question, previous=None)` now returns `(query, year)`.
- The `doc_types()` import and call were removed from `build_rag_graph`.
- The `full` experiment mode still works: `compare_retrieval.py` has its own `TYPED_REWRITE` prompt derived from `REWRITE`.

### 5. Embedding model made configurable (`rag/store.py`)
- `EMBED_MODEL` environment variable, default `BAAI/bge-small-en-v1.5`.
- For any non-default model, the collection name gets a suffix, for example `arla_parent_bge-base-en-v1.5`. The default model's collections are unchanged, so no other script needed edits.

### 6. `compare_retrieval.py`
- Rewrites are cached in `eval/rewrites.json`, so different embedding models see identical queries.
- Prints the model name and retrieval ms per query.

### 7. Diagram
- `docs/agent_diagram.html`: the full agent graph as inline SVG (blue = uses the LLM, grey = rules only, dashed = loop back). It is generated by a script in the session scratchpad, which is not kept in the repo, so edit the HTML or regenerate it by hand if the graph changes.

## Things explained this session (so you can re-read them in the code)

- **Routing and fan-out:** `route_after_plan` returns `Send` objects for parallel RAG copies plus `"web"`. List fields use `operator.add` reducers. `gather` is the join (separate `add_edge` calls, so lookups with no web branch still reach it). The critic retry reuses the same mechanism, and rounds are filtered by `round`.
- **Ingestion and chunking:** page-by-page PDF loading, cleaning, recursive chunking (800/150) vs parent-child (parent 1,500/200, child 300/50), bge-small, Chroma with cosine distance.
- **RAG subgraph:** rewrite, retrieve, grade (best distance at or below 0.30 is relevant, above 0.45 is not, in between asks the LLM), generate. On a retry the rewrite gets a "different keywords" hint and the year filter is dropped.
- **News pipeline:** snapshot loader (the agent never uses live mode), cleaning with fuzzy deduplication, FinBERT sentiment cached on disk, regex event flags, per-company summary.
- **Policy comparator:** retrieval restricted to 10 policy document types, newest year only, distance limit 0.35, one LLM verdict that is validated by rules.
- **Risk scorer:** pure function with four weighted dimensions (policy 0.4, regulatory 0.2, external 0.2, evidence 0.2), a hard floor for bribery, human-rights, supplier-code and modern-slavery conflicts, and all numbers in `config/risk.json`.
- **Synthesizer and critic:** code builds every factual section and the LLM writes one summary paragraph that is not itself checked. The critic is rule-based: citations exist, figures appear in the cited passages, the quote matches the sources, plus the risk flag.
- **Non-retrieval tool requirement:** satisfied by the news pipeline and the risk scorer. The policy comparator starts with retrieval, so it should not be presented as the non-retrieval tool.
